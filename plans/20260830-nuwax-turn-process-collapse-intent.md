# 意图：Nuwax 普通会话工作轨迹折叠

- 日期：2026-08-30　发起人：用户
- 状态：已接受（用户，2026-08-30）

## 问题

普通会话的长任务会把思考、系统上下文、提问、中间说明、子智能体与大量工具调用全部平铺在消息流中。即使已有按消息的局部折叠，跨消息的同一轮任务仍会形成长页面，最终总结也容易与过程内容混在一起，用户难以快速读取结果或按需回看执行轨迹。

## 预期结果

- 每轮助手工作过程聚合为一个可展开/收起的轨迹区，折叠后页面只保留摘要行与最终总结。
- 折叠头按可用数据展示工具调用次数、非工具过程消息数和工作耗时。
- 最终助手总结始终在折叠区外，以完整 Markdown 正常展示。
- 运行中的最新过程可见，完成后默认收起；用户手动选择不会被流式更新覆盖。
- 历史回放与实时会话一致，鼠标和键盘均可操作。

## 受影响的用户与系统

- 用户：使用 Nuwaclaw 普通会话执行长任务、查看历史任务结果的桌面端用户。
- 系统：`nuwax/` 子模块普通会话渲染层、会话消息投影、Markdown 过程组件及 Mock 验收。
- 父仓仅增加需求/规格/计划工件并更新子模块 pin；Electron 主进程、IPC、agent-kit 与 Rust helper 不变。

## 约束

- 仅覆盖普通会话；AppDev、移动端和后端协议不在本期范围。
- 不使用会话级长期记忆 `ConversationInfo.summary` 充当本轮最终总结。
- 待回答的审批或提问卡必须保持可见，不能因过程折叠阻塞用户操作。
- compact / normal / detailed 三档密度继续生效，但三档都应具备可手动折叠的统一结构。
- 新文案进入现有 i18n 体系；不硬编码单一语言。
- 不 push、不打 tag、不发布。

## 开放问题

- 无。折叠范围、流式行为、标题指标、零工具口径、普通会话范围及最终总结样式均已由用户确认。
